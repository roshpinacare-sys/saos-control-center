# כספת-הריפו הריבונית (Sovereign Repo-Vault) · EXEC-CD-24

> הוראת-המפעיל: **"תקים ארנק ותכניס אותו היטב לכספת בריפו שלא יהיה תלוי בסנדבוקס שנחמק.
> תקים שם כתובת מה שצריך ותשתמש ותשמור את הפרטים ותלמד גם את האוטונומיה לעשות דברים כאלה."**

## מה-זה

כספת-המפתחות הראשונה של הריבונות שחיה-**בגיט עצמו** — לא בסנדבוקס, לא ב-.env, לא ב-tmpfs.
כל-הכספות-הקודמות (`keys/`, `agent/vault/`, `.secrets/`, `~/.devgate/secrets/`) מתו-עם-הסנדבוקס
(EXEC-CD-22: `fleet_keys.enc wiped` — מתועד). כספת-זו הפוכה: **clone חדש של הריפו = שחזור-מלא**.

## תרגיל-השחזור (Recovery Drill — החוק)

סנדבוקס-מתה → מכונה-חדשה:

```bash
git clone <repo> saos && cd saos && bun install
bun scripts/repo-vault-open.ts --probe   # פתיחה-GCM + נגזרה-מחדש + בדיקות-חי
```

התרגיל מוודא: פענוח-GCM תקין → נגזרה-מחדש מה-mnemonic **ביט-מול-ביט** → עקביות-מול-`manifest.json`
→ בדיקות-חי-מול-RPC-ציבורי. אם-משהו-לא-מסתדר — הסקריפט צועק-בכנות ולא משקר.

## יושר-איום — כנות-לפי-חוק-הכנות

- מה-ההצפנה נותנת: אף-מפתח-עירום-בקובץ, הגנה-מפני-סריקות-אוטומטיות, מפתח-שלא-ידלוף-ללוג,
  ומודעות-מלאה שפתיחה = פעולה-מכוונת (סקריפט/ספרייה).
- מה-ההצפנה **לא** נותנת: הגנה מבעל-גישה-לריפו-הפרטי שמתכוון-לפתוח (שני-השברים-בריפו).
  זה-המחיר של עצמאות-מסנדבוקס — המפעיל הורה-עליה-במפורש וקיבל-את-המסחר-הזה.
- אף-פעם: לא לרשום מפתח-פרטי בלוג/DB/API/קובץ-עירום. לא לפתוח-ולהשאיר-בזיכרון-שרת.

## קשר-למערכות-הקיימות

- **ROT1/headcorner** (Steem/Hive/Blurt) — זהויות-השרשרת-החברתית; מנוהל-בנפרד לפי-חוק-המפתחות.
- **זהויות-הדלת** (saos-dex deposit identities) — נגזרות-דטרמיניסטיות ממנוע-ה-DEX; לא-נוגעים.

  וקרקע לתשלומי-תשתית. מתאים-ישירות לזרימת-הביצוע של EXEC-CD-23 (Maya deposit+memo → יעד-זה).
